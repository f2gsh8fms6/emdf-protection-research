Dolby DD+ Atmos · ETSI TS 102 366 Annex H

The 40 bits that gate Dolby Atmos

Every DD+ Atmos frame carries an emdf_protection field the specification deliberately refuses to define. It turns out to be two truncated HMAC-SHA-256 tags with a key embedded in the reference encoder. Here is the whole construction on one page.

§H.2.2 — the calculation of protection_bits_primary / protection_bits_secondary is “implementation dependent and is not defined in the present document.”

1 · What the signer hashes: the frame with holes

The tag does not cover the emitted frame. The Atmos muxer splices metadata into the middle of an ordinary E-AC-3 frame, and the authenticated view — covered — is the pre-splice core: from bit 32 (fscod) on, with every spliced region excised. Schematic, not to scale:

The EMDF body itself — everything after its 16-bit sync 0x5838 and 16-bit length — is the second message, container, with the 40 protection bits written as zeros while hashing. The splice must be undone bit-exactly: the hole boundaries are found by walking the E-AC-3 BSI and audio-block syntax field by field (coupling included). That walk is where every implementation actually gets its bugs.

prim(32 b) = HMAC-SHA-256(key, covered ‖ container)[0:4] sec (8 b) = HMAC-SHA-256(key, digest₁)[:1] key_id(3 b) = 0 in every DEE frame key = unhex("2c16951c38232060d8975aa6cbdc54813142dc269dcc5d437697206c93871de4") with every byte XOR 0x7a # obfuscated hex constant inside # dee_audio_filter_ddp_atmos.so (DEE) = 566cef66 42595a1a a2ed20dc b1a62efb 4b38a65c e7b62739 0ced5a16 e9fd679e

The hash itself is stock SHA-256 — standard IV and round constants, textbook ipad/opad blocks. The only interesting bits are which bytes are hashed and the secondary tag's dependence on the untruncated primary digest. A config table in DEE can override the embedded key per payload-id; without licensed key material, the default above is what ships and what it signed with.

3 · Proof, twice over

Two independent implementations of the construction agree with the reference encoder on every frame — including the 8-bit secondary, which a pre-fix third-party signer left zero:

32 / 32
frames of a genuine DEE stream: prim + sec recomputed from the emitted bits alone (emdf_tool.py verify)
125 / 125
frames of an iclforge stream, signed then verified incl. sec, under an independent Python implementation
8 / 8
frames matched against gdb-captured hash inputs (the literal bytes DEE fed its hash contexts)
32 / 32
single-bit edits detected after corrupt re-stamps the frame CRC — only the tag catches the edit

4 · What it settles — and what it doesn't

settled
Algorithmstock HMAC-SHA-256, truncated 32 + 8 bits; not a CRC (an exhaustive CRC-8/CRC-32 sweep found no match that held across frames)
Authenticated viewthe pre-mux core from bit 32, holes excised, rounded to the nearest 16-bit word — the whole infomdat element is a hole, flag and body together
Secondary taga second HMAC over the full 32-byte primary digest; a verifier ignoring it accepts tampered frames, a signer leaving it zero fails a complete verifier
Hardware (Apple TV)tvOS 27.0 checks the seal and accepts this construction: a signed iclforge stream decodes its objects, and one wrong tag bit mutes the whole stream
